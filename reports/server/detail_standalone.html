    Method

    1. Lay out the stock compiler (main @ 99406265) and the server branch the way the .NET SDK ships fsc: ReadyToRun per assembly, Server GC runtimeconfig.
    2. Replay each compilation captured from a real dotnet build FSharp.Compiler.Service.slnx. Process configs run dotnet fsc.dll @rsp; server configs send the same response file to a worker over its socket, exactly as the Fsc task does.
    3. Per config: 1 warm-up round (a fresh worker compiles each project once), then 5 measured rounds over the 5 projects. Configs run one after another (batches e1–e5 on the same day and machine).
    4. Record per run: wall and CPU time (process: rusage; worker: its own CPU delta), the compiler's --times phases and, for workers, GC pause, allocations and GC counts measured inside the worker.
    5. Report medians with a 95% bootstrap CI on every change; a change counts only when its CI excludes zero. Every server config produced assemblies identical to stock.

    Do the flags behave differently on SDK 10 and SDK 11?

    • These are the compilers as shipped in each SDK, with no changes to SDK files, run on the same captured compilations.
    • The flags are set as env vars on the fsc process. Configs are interleaved in shuffled rounds.
